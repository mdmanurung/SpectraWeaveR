# Plan: automatic, manual and adaptive gating

Date: 2026-11-10. Status: **awaiting approval**. No gating code written.
Sources: code map of R/gate.R, R/gating_utils.R, R/unmix.R (Explore agent); tool survey
(general agent); OMIQ AdaptiGate page and Montante et al. 2025 bioRxiv 10.1101/2025.10.07.679685
(web agent). Licences checked with `gh api` or Bioconductor pages, marked where unverified.

## Where the package stands

- Nine gating functions. All are automatic re-fits or fixed coordinates. None plots a gate,
  transfers a gate from a reference, reports how far a gate moved, or imports/exports FlowJo or
  GatingML gates.
- Hidden thresholds (against the house rule "impactful choices are required arguments"):
  `nmad = 4` in `sw_gate_singlets()` (R/gating_utils.R:52), `nmads = 4` in the two doublet
  filters (gating_utils.R:152, 224), `min = 50000` and `K = 2` in `sw_gate_template()` rows
  (R/gate.R:104, 110, 136), `cofactor = 6000` in `sw_gate_run()`.
- Likely bug: `sw_filter_margins()` passes only `names(channel_specs)` to PeacoQC, so the user's
  ranges are dropped (R/unmix.R:1668).
- Doublet and debris filters drop events without reporting how many.

## What AdaptiGate is (public description)

OMIQ: "Gate a template file, and AdaptiGate fits those gates to each file in your dataset."
OMIQ points to Montante et al. 2025 (flowMagic, R, **Apache-2.0**,
github.com/semontante/flowMagic, last push 2026-08-06): a random forest on 36 density and
expression features per bivariate plot, a template model (trained on the user's gated files) and
a generalised model. Reported macro F1 0.90 (template) and 0.78 (generalised) for abundant
populations, 0.65 and 0.42 for rare ones, against flowDensity gates on 92,203 files. Whether
flowMagic is the engine inside OMIQ is OMIQ's claim. No per-file confidence or gate-shift number
is described.

## Proposed modules

| # | Module | What it does | Route |
|---|---|---|---|
| G1 | Gate QC | Per sample and gate: share of events kept, share near the gate edge, centroid shift and kept-share z-score against the cohort or a reference, flag when a landmark is not found. Numbers only, a `sw_diagnose()` module. | own code |
| G2 | Landmark gate transfer | Gate drawn on a reference sample; for each new sample, find 1D density landmarks (peaks/valleys) per gate axis, map reference landmarks to the sample's, move gate vertices by the fitted shift (and optionally scale). Report the shift as the G1 QC number. Refuse when landmarks are missing. | own code, idea from flowStats gaussNorm/warpSet (Artistic-2.0) and flowLearn (no licence: idea only) |
| G3 | flowMagic wrapper | Template-trained and generalised ML gating as an option, from Suggests. Per-sample gates back into a GatingSet; G1 scores them. | wrap (Apache-2.0) |
| G4 | Density pre-gates | Debris, singlets, live, lymphocytes, CD3+ with per-sample valley/percentile thresholds; every threshold a required argument. | own code, idea from flowDensity (Artistic-2.0); openCyto plugins wrapped (AGPL) |
| G5 | Reproducible manual gating | Gates stored as data (tibble of vertices + GatingML file); draw interactively with flowGate (MIT) or by coordinates; import/export FlowJo/GatingML via CytoML (AGPL, wrap) or flowkit (Python, BSD-3). | wrap |
| G6 | Gate plots | Overlay a gate (reference and adapted) on each sample's scatter; hierarchy view. | own code (ggplot2) |
| G7 | Fix existing functions | Make hidden thresholds required; fix the margin-range bug; report events removed. | own code; **breaking change** |

Benchmark: inject known shifts and rescales into real files (the Aurora extract; Glehr BAD/FORT;
CytoBatchFlagR) and score each method's gates against the gate on the unshifted file (F1 per
population, events), plus G1's shift against the injected shift.

|---|---|---|---|
| GD1 | Which modules to build | G1, G2, G6, G7 first; G3, G4, G5 next | G1 is the QC the goal asks for; G2 is the open AdaptiGate-like path with a QC number |
